# nano-claw-tracker

## Цель

Собрать простой, надежный трекер тренировок с возможностью адаптировать нагрузку под текущее состояние организма на основе данных Oura.

Система должна решать две задачи:

1. **Статический трекер прогрессии**
   - фиксировать тренировки
   - отслеживать прогресс по базовым упражнениям
   - рекомендовать следующий шаг по весам и объему

2. **NanoClaw + Oura API**
   - регулярно забирать свежие данные из Oura
   - оценивать текущее состояние
   - подстраивать тренировку дня под readiness / сон / HRV / resting HR / накопленную усталость

---

## Контекст пользователя

Текущий ритм активности:

- 2 силовые тренировки в неделю, около 1 часа
- 1 бассейн в неделю
- утренняя йога-разминка ~10 минут ежедневно
- прогулки пешком ~1 час ежедневно

Цель:

- база
- мобильность
- долголетие
- устойчивый прогресс без перегруза

---

## Продуктовое видение

Это не должен быть “умный фитнес-комбайн”.

Это должен быть **простой личный тренер-ассистент**, который отвечает на четыре вопроса:

1. Что мне делать сегодня?
2. Насколько тяжело мне сегодня тренироваться?
3. Прогрессирую ли я?
4. Когда лучше притормозить?

3. Жим стоя — 3x5–6

5. Kettlebell swing — 3x12–15

## Режимы нагрузки

### FULL
Используется, когда восстановление хорошее.

Что делать:
- полный объем
- рабочие веса по плану
- разрешена прогрессия

### BASE
Нормальное состояние, но без ощущения “идеального дня”.

Что делать:
- основной объем сохранить
- без агрессивного повышения веса
- работать с 1–2 повторами в запасе

### LIGHT
Используется, когда восстановление просело.

Что делать:
- снизить вес на 10–15%
- убрать 1 подход у основных движений
- убрать или сократить добивку
- задача — сохранить ритм, а не геройствовать

---

## Правила прогрессии

Базовый принцип:

- если все рабочие подходы выполнены чисто и остался запас 1–2 повтора:
  - +2.5 кг для верхней части
  - +2.5–5 кг для нижней части
- если техника плывет или RPE слишком высокий:
  - оставить тот же вес
- если два раза подряд провал:
  - откатить вес на 5–10%

Дополнительно:

- аксессуары прогрессируют прежде всего по повторам
- подтягивания: сначала повторы, потом дополнительный вес
- свинги: сначала качество и взрыв, потом объем

## Разминка

Цель разминки:

- слегка поднять температуру тела
- включить нужные суставы и паттерны
- не утомить до начала работы

Протокол:

1. Легкий разогрев 3–4 минуты
   - велосипед или эллипсоид
2. Динамическая мобилизация 5–6 минут
   - hip circles
   - leg swings
   - cat-cow
   - thoracic rotations
   - arm circles
   - band pull-aparts
3. Активация 2–3 минуты
   - glute bridge
   - dead bug / plank
4. Подводящие подходы перед первым основным движением

Не делать перед силовой как основной инструмент:

- длинный бег на дорожке
- долгую статическую растяжку

## Какие данные брать из Oura

Для первой версии нужны только самые полезные сигналы.

### Основные метрики
- readiness score
- sleep score
- HRV
- resting heart rate
- sleep efficiency
- температура / deviation, если доступно
- total sleep time
- active calories / activity balance, опционально

### Производные метрики
- rolling 7d average
- rolling 28d baseline
- delta к baseline
- тренд 3 дня
- количество дней с ухудшением подряд

---

## Логика принятия решения

Система не должна быть магической. Правила должны быть прозрачными.

### Пример простой логики

#### FULL
Если:
- readiness >= 85
- sleep score >= 80
- HRV не ниже baseline больше чем на 10%
- resting HR не выше baseline больше чем на 3 bpm

#### BASE
Если:
- readiness 75–84
- или sleep score 70–79
- или HRV просел умеренно
- или resting HR слегка выше baseline

#### LIGHT
Если одно из условий:
- readiness < 75
- sleep score < 70
- HRV сильно ниже baseline
- resting HR заметно выше baseline
- плохое субъективное самочувствие
- предыдущая тренировка была очень тяжелой и прошло мало времени

---

## Добавить субъективные данные

Oura полезен, но не всесилен.

После каждой тренировки логировать:

- session RPE (1–10)
- мотивация / энергия (1–5)
- soreness (1–5)
- комментарий

Это даст более честную картину, чем голые wearable-метрики.

## Формулы и derived metrics

### Estimated 1RM
Можно использовать формулу Epley:

estimated_1rm = weight * (1 + reps / 30)

Она не идеальна, но для домашнего трекинга достаточно хороша.

### HRV delta
hrv_delta_pct = (current_hrv - baseline_hrv_28d) / baseline_hrv_28d * 100

### Resting HR delta
resting_hr_delta = current_resting_hr - baseline_resting_hr_28d

## Интеграция с Oura API

## Что важно учесть

- использовать **server-side OAuth2**
- хранить access token и refresh token безопасно
- регулярно обновлять токены
- делать sync по расписанию, например 1–2 раза в день

### Почему не client-side only
Потому что это временно, менее удобно и хуже подходит для фоновой автоматизации.

---

## Поток авторизации

1. Пользователь открывает ссылку авторизации
2. Подтверждает доступ Oura
3. Backend получает authorization code
4. Обменивает его на access token + refresh token
5. Сохраняет credentials
6. Scheduler запускает регулярный sync

---

## Поток синхронизации

1. Scheduler запускается утром
2. Sync service тянет нужные daily metrics
3. Данные записываются в recovery_snapshot
4. Daily state пересчитывается
5. Rule engine выдает recommended_mode
6. Агент формирует daily brief

## Rule engine

Логика должна быть декларативной и редактируемой.

### Псевдокод

```python
def decide_mode(readiness, sleep_score, hrv_delta_pct, resting_hr_delta, session_rpe_prev, soreness):
    score = 0

    if readiness >= 85:
        score += 2
    elif readiness >= 75:
        score += 1
    else:
        score -= 2

    if sleep_score >= 80:
        score += 2
    elif sleep_score >= 70:
        score += 1
    else:
        score -= 2

    if hrv_delta_pct >= -10:
        score += 1
    else:
        score -= 1

    if resting_hr_delta <= 3:
        score += 1
    else:
        score -= 1

    if session_rpe_prev >= 9:
        score -= 1

    if soreness >= 4:
        score -= 1

    if score >= 4:
        return "FULL"
    elif score >= 1:
        return "BASE"
    return "LIGHT"
```

## Правила переключения тренировки

Если сегодня запланирован день A или B, система должна учитывать:

- сколько дней прошло с прошлой силовой
- какая была предыдущая тренировка
- был ли пропуск
- насколько тяжелой была последняя сессия

Пример:

- если последняя была A → следующая B
- если был долгий перерыв > 7 дней → вернуться в BASE
- если было 2 LIGHT подряд → не форсировать прогрессию, даже если один день внезапно FULL

## Риски

### 1. Переусложнение
Самый главный риск. Есть опасность строить “идеальную систему”, пока нет даже 4–6 недель качественных логов.

### 2. Слишком много метрик
Большинство метрик не добавят пользы. Нужен жесткий фокус на 4–6 сигналах.

### 3. Wearable bias
Oura может подсказать состояние, но не должен полностью заменять субъективное ощущение и здравый смысл.

### 4. Ложная точность
Не нужно делать вид, что правило “readiness 83 vs 84” радикально меняет жизнь. Это всего лишь ориентир.

---

## Рекомендация по старту

Самый разумный путь:

1. оставить статический трекер как основной источник истины
2. 4–6 недель честно логировать тренировки
3. параллельно сделать простой local rule engine
4. только после этого подключать Oura API и NanoClaw

Это даст:
- меньше суеты
- лучшее качество правил
- реальную полезность, а не красивую инженерную игрушку

## Что должно получиться в итоге

Идеальный результат v1:

- утром агент говорит, какой режим у тебя сегодня

- после тренировки быстро логируешь факт
- раз в неделю получаешь summary:
  - прогрессируешь или нет
  - накапливается усталость или нет
  - нужно ли держать темп или чуть отпустить

## Definition of Done для v1

Версия v1 считается успешной, если:

- ты реально используешь ее минимум 4 недели
- агент ежедневно выдает понятную рекомендацию
- рекомендации не раздражают и не противоречат здравому смыслу
- логирование занимает не больше 2–3 минут
- видно прогресс хотя бы по 2–3 базовым движениям
- система помогает не пропускать тренировки и не перегружаться
